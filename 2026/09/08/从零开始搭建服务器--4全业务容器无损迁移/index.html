从零开始搭建服务器--4全业务容器无损迁移

服务器主打一个哪家便宜用哪家，但总会有个问题，之前的鸡上的数据不方便拷贝，又或者哪怕拷贝了也会因为各种原因不同步，那就可以用到 rsync。

总的来说，就是把服务器 A 所指定的目录结构包括内容，整个照搬到 B 上。

rsync 作为下载器或者本地同步的用法不再多赘述，所以本文就直接讲一下两台公网 IP 的鸡之间的同步。

至于为什么不演练？因为我懒.jpg

二、安装 sshpass

两台机器之间不想折腾 SSH 密钥，直接走密码连接。在目标机器（新机器）上安装 sshpass，可以免去每次手动交互敲密码的麻烦：

三、拉取老机历史命令并归档

为了保留老服务器的操作记录，且防止以后换过多台机器导致历史混乱，在新机器上创建一个专用的历史归档目录 /root/vps_histories，将老机历史命令拉取过来并打上对应 IP 的标签：

四、备份 Docker 命名卷数据（Aether PostgreSQL）

如果项目使用了 Docker 的命名卷（例如 postgres_data:/var/lib/postgresql/data），其数据是存放在宿主机 /var/lib/docker/volumes/ 下的，并不在项目目录内。

最稳妥的做法是在同步前，先在老机器上将数据库导出为一个 SQL 文件，直接存放到项目目录中，方便稍后随项目一起同步带走：

五、精准同步业务子目录（切忌整盘覆盖）

以我自己现在存在的服务为例，老机器上一共有 4 套 Docker 项目：

  • qqbot（QQ 机器人综合生态）：内部编排了 4 个服务，包含 napcat（QQ客户端与登录态）、koishi（机器人核心框架）、rsshub（自建 RSS 订阅服务与 B 站 Cookie 凭证）、browserless（提供无头 Chrome 给 RSSHub 动态抓取）。
  • **sub2api-deploy**：Sub2API 聚合网关（含应用、Postgres 数据库与 Redis 缓存）。
  • **Aether**：Aether 知识库（含应用、Postgres 数据库与 Redis 缓存）。
  • **CLIProxyAPI**：CLIProxyAPI 代理服务（含 auths 账号凭据与全局路由）。

千万不要直接敲 rsync ... /root/ /root/ 整盘覆盖，否则不仅会把老机根目录下的无用垃圾（比如几 GB 的 .codex、.vscode-server、.npm）全带过来，还可能冲掉新机器原本的文件。

最稳妥的做法是：按具体的业务项目子目录，一条一条对齐搬迁。

参数说明：
-aHAXz --numeric-ids：非常重要，不仅会递归和压缩传输，还会把 Linux 底层的 文件硬链接、权限、数字 UID/GID（比如 Postgres 的 UID 70） 原封不动保留，防止数据库搬过来后报权限错误崩溃。

六、新机独立服务启动测试（Sub2API、Aether、CLIProxyAPI）

在切换需要防顶号风控的 QQ 机器人之前，先在新服务器上启动其余 3 套完全互不影响的独立业务进行验收测试：

确认容器全部处于 healthy 健康状态且 HTTP 服务正常响应后，先将容器停机待命（等待后续全量割接）：

七、QQ 机器人业务毫秒级停机割接（防风控与双重登录）

QQ 机器人（基于 Napcat、Koishi、Browserless、RSSHub）由于维护着活跃的 QQ 长连接 Session，两台服务器同时登录必定会触发腾讯的风控顶号和异地冻结。

为了做到既不触发风控、又消灭割接中断时间，必须遵循 “提前预拉取镜像 -> 老机秒级停机 -> 极速增量补漏 -> 新机秒级拉起”：

1. 新机提前预拉取镜像（切忌停机后再下载）

因为包含完整的 Chrome 和 Napcat 镜像，体积较大（数 GB）。如果停机后再下载会造成长达数分钟的离线时间。因此在割接前，先在新机后台将镜像预先拉好：

2. 执行停机割接（全程 2~3 秒）

当镜像已经就绪后，执行极速停机与补漏拉起：

八、新机服务全量启动与防火墙开放

所有业务确认就绪后，启动所有服务并开放新机对应端口：

九、编写自动化增量同步脚本

为了避免每次手动敲命令，在新机器上写一个增量同步脚本 /root/sync_from_old.sh。

日志直接按年份命名（如 /var/log/vps_sync_2026.log），一年一个文件，既方便以后迁移归档，也不会在目录下产生碎文件。

十、配置每日定时任务

确认新机器时区为 Asia/Shanghai，通过 crontab 设置每天凌晨 05:00 自动触发同步，执行完即退出，无需常驻守护进程。

十一、全面验证与收尾

在新机上检查容器运行状态、端口监听与日志，确保各业务运行正常。
